PHOENIX CI

self-healing PR review — agents propose, deterministic code decides.

Paste a pull-request link. A planner agent reads the real code and drafts a typed fix plan. An implementer agent applies it inside an isolated sandbox and runs the project's actual test suite. If that worker dies mid-flight, a supervisor notices via heartbeats/leases and reassigns the work to a fresh worker — nothing is lost. And no matter what any agent claims, the merge gate opens only for a genuine passing test run.

Why it doesn't hallucinate its way to a merge

TYPED PLANS

The model returns a structured plan ({edits:[{path,content}]}) parsed and path-validated — prose is never executed.

FENCED SANDBOXES

Every attempt clones the PR head into a throwaway copy. A killed worker leaves nothing behind for the next one to trip over.

LEASES + FENCING

Heartbeats renew a lease. Miss them and the supervisor declares death and reassigns. Zombie results from old attempts are rejected by attempt-number fencing.

PROVENANCE-GATED MERGES

The gate reads a report stamped by the real test runner. “Trust me, tests pass” from an agent is structurally impossible to act on.
